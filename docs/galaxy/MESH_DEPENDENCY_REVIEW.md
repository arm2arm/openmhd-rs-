## Numbered findings

### D1 — Distribution blocker: missing additive `glam` third-party notices

**Locator/evidence.** `license_materials.json#/packages/registry+https://github.com/rust-lang/crates.io-index#glam@0.27.0` retains only `LICENSE-APACHE` and `LICENSE-MIT`, with no source notices. The exact checked archive (SHA-256 `9e05e7e6723e3455f4818c7b26e855439f7546cf617ef669d1adedb8669e5cb9`) also contains `ATTRIBUTION.md`, 3,718 bytes, SHA-256 **`9f0738ead3dcc72bac87afc652c2466e1bc130d235db7798f98da4d4ef013639`**. Its §§DirectXMath, Realtime Math and GLM, lines 11–28, 36–54 and 62–80, supply three full MIT notices: Microsoft Corp (2011–2020), Nicholas Frechette (2018), and G-Truc Creation (2005). `README.md` lines 245–255 explicitly says the crate contains ported code and points to this file.

These notices are additive to the election for `glam`'s own code. Choosing Apache-2.0 does not erase the MIT notice conditions on those incorporated portions. The materials collector recognizes selected license/notice filename prefixes (including AUTHORS) and selected code comments; it misses this Markdown attribution file. Hash closure of that collector's output therefore does not establish notice closure.

**Independent primary check.** The [pinned upstream file](https://raw.githubusercontent.com/bitshifter/glam-rs/9f694bcc56808716eb269a5489a214b4e47df026/ATTRIBUTION.md) exactly matches the archive. Its Git blob is `34ae900e9c0706e51b9bb78a8fc0c8f1a8a03be8`, present in an independently retrieved, nontruncated 251-entry complete tree at the archive's published commit `9f694bcc56808716eb269a5489a214b4e47df026`. This is an identified material omission, not evidence of absent permission.

**Resolution/gate.** Add the exact file and provenance to a revised materials packet and closed inventory, preserving all three notices in source and binary release materials when distributing the corresponding code. Retaining the entire file is the bounded, conservative choice; do not rely on unmeasured linker removal to discard notices. Recheck the revised packet and release layout without weakening this requirement. No numerical experiment resolves this documentary omission.

### D2 — Supported scope: selected feature graph excludes optional LGPL backends

**Locator/evidence.** Scratch `Cargo.toml` dependency stanza; `audit.json#/graphs`; published mesh `Cargo.toml.orig` §§dependencies/features; `src/lib.rs` lines 70–92 and `src/geometry.rs` lines 4–18, 296–310. The latter two retained metadata files are byte-identical; this establishes equal captured package graphs, not equal native execution.

The mesh node enables only `ibig`; its six direct dependencies are `ahash`, `document-features`, `glam`, `ibig`, `num_enum` and `rstar`. `ibig 0.3.6` has no enabled features and uses `cfg-if` and `static_assertions`. Default mesh features would enable `ibig` **and** `rayon`; defaults are disabled here. `rayon`, `rug`, `gmp-mpfr-sys`, `malachite-base`, `malachite-nz`, `dashu`, `num-bigint` and `hdf5` are absent. The actual backend imports are feature-guarded, and the crate rejects simultaneous named integer backends. This is source/graph evidence only; it does not establish successful compilation or absence of every future build effect.

The four additional unfiltered nodes are `r-efi`, `wasip2`, `wit-bindgen` and `zerocopy-derive`. Getrandom's UEFI and WASI conditional edges do not reach the two selected platform graphs. The unfiltered `zerocopy-derive` edge carries `cfg(any())`, which is false: **33 is a conservative unfiltered metadata/locked-archive inventory, not 33 packages proved build-reachable on one target**. Host proc-macro/build dependencies also must not be equated with code shipped in a final runtime binary.

**Resolution/gate.** Preserve the exact feature selection. Recompute and review the real workspace's resolved graph after integration, including host/build and target distinctions, cfg/backend overrides, feature unification and lock changes. One dependency's `default-features=false` does not prevent another dependency enabling features of the same package. This follows Cargo's [feature-unification rules](https://doc.rust-lang.org/cargo/reference/features.html); the retained graph is a specific observation under the [metadata format](https://doc.rust-lang.org/cargo/commands/cargo-metadata.html). Optional LGPL paths do not impose LGPL obligations on the absent paths in this candidate.

### D5 — Packaging prerequisite: an audit database is not a release notice bundle

**Locator/evidence.** `collect_license_materials.py` filename/comment selectors; `license_materials.json#/limitations`; Apache-2.0 §4; MIT/Unicode and the per-file conditions above. A broader read-only textual inspection also found source provenance outside the retained comment set: `heapless/build.rs` lines 51–53 (anyhow 1.0.63, explicitly MIT OR Apache-2.0) and `src/pool/arc.rs` lines 65–68 (Rust alloc 1.63.0, same alternatives). These support the selected Apache path; preserve the provenance comments when distributing source. Non-Rust shell/Markdown/TOML/CSS copyright headers in the zerocopy archives are likewise outside the collector's code-extension filter. Keep them in a vendored source distribution. None of these observations demonstrates a new incompatible grant; they demonstrate why 213 selected comment records are not a complete source-notice census.

No NOTICE-named file was found in the 33 archives; the four retained complete-tree license-path receipts also supply no separate NOTICE. Do not invent an upstream NOTICE obligation, but do not discard actual attribution simply because its filename differs. Apache [§4(a)–(d)](https://www.apache.org/licenses/LICENSE-2.0) requires a license copy, prominent notices in modified files, pertinent source notice retention, and readable applicable upstream NOTICE attribution when one exists. Section 6 does not grant general trademark rights. These conditions permit distributing OpenMHD's own MIT code alongside dependencies under their elected terms; they do not relabel the dependencies MIT or require electing all OR alternatives.

**Concrete prospective layout and release check.** Keep OpenMHD's `LICENSE` for its own code. Add a readable `THIRD_PARTY.md` identifying package/version, election, archive checksum and material locations. Under `licenses/<name>-<version>/`, retain original material filenames, including the upstream-root Apache supplements for rstar/wasip2, mesh README grant plus a full Apache copy, r-efi `AUTHORS`, unicode-ident `LICENSE-UNICODE`, full libm `LICENSE.txt` plus a path-labelled exact source-notice bundle, and glam `ATTRIBUTION.md`. Keeping all originally offered license texts is acceptable conservative packaging, with the chosen option clearly identified; it does not make alternatives cumulative.

For a vendored source release, preserve the original complete archive sources/headers, include supplements, and mark any modified dependency files prominently. For a binary, installer or container release, ship readable license/attribution files with the artifact; a compressed developer audit JSON or build-time registry cache alone is insufficient. Preserve libm's binary notices and glam's three MIT notices. Include notices for what is actually redistributed; retaining the entire audited set is a conservative alternative. Do not assert that every locked host-only or unreachable package is incorporated into a Linux binary. If all 33 archives are bundled, their distribution terms all apply to that source bundle. Inspect the final artifact and index after the actual build; no such artifact was produced here.
