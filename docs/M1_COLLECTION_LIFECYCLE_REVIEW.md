## Numbered findings and dispositions

1. **High — a failed post-signal registry write can restore apparent authority to signal a stale descendant group.** In C:428–465, cancellation marks `cancelled` only in memory, sends `SIGKILL` at line 461, then changes/publishes `state='kill_sent'` at lines 464–465. If that publication raises, the lock releases and the persisted node can still say `active`, with its old guardian PID and no cancellation fence. `cancel()` reports `CleanupIncomplete` (C:419–426), but the automatic exception path calls cancellation again at C:681, and pool/outer cleanup can also revisit the same registry.

   The direct-owner safeguard at C:448–454 checks `self.process.returncode` only for `key == self.node_id`. It does not apply to a selected separately owned descendant. A concrete source interleaving is: an ancestor cancellation kills descendant B; B's post-signal publication fails; B's own caller reaps B through `communicate`; before that caller can publish `leader_lost` or other closure, an ancestor cancellation pass rereads B's still-`active` node and signals its old numeric PGID. The second pass need not hold B's `Popen` object. If the ID has been reused, the signal can target a different group. Even without an observed reuse, the protocol has lost its asserted held-leader authority. This loss originates in its own signal/write ordering, rather than requiring an external daemon escape or arbitrary guardian death. The ancestry launch fence can likewise be absent after a failed publication despite a signal having been sent.

   **Required repair:** publish a cancellation fence that descendants/other owners can observe before any signal, and persist an explicit one-shot signal intent/uncertainty state before the irreversible signal operation. A publication failure must not leave another owner entitled to interpret that node as an unsignalled active held leader. Do not retry an old numeric group merely because its stale file still says `active`; distinguish unattempted, attempted and uncertain signal delivery without inventing a successful cleanup. Keep the shared lock, private-session checks and unfinished/external-evidence behavior. This is a source-control-flow finding, not an exercised accidental signal or observed PID reuse.

   **Smallest additional REANA control:** a harmless nested ownership fixture with recorded/mocked signal dispatch, injecting failure at the signal-state publication boundary and a barrier after the nested caller's reap. Have a distinct ancestor cleanup pass inspect the same persisted node; it must not issue a second signal under the old authority. Also assert that a failed pre-signal fence prevents a new launch rather than claiming cancellation completed. No actual unrelated process, numerical workflow or complete physical packet is needed.
